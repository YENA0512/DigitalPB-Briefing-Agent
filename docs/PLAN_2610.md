## 2. 왜 바꿨나

### 2-1. 출처 코드는 고객의 언어가 아니다

`[일간-261012]`는 grounding 심사가 **대조할 수 있는 라벨**이어서 생긴 것이고,
고객이 읽을 이유가 없다. 그런데 초판은 그 문자열을 그대로 노출했다.

고객이 근거를 확인하고 싶을 때 필요한 것은 코드가 아니라 **그 콘텐츠로 가는
길**이다. 그래서 출처를 ①②③ 로 바꾸고, 누르면 제목·요약·발행처가 펼쳐지고
다시 누르면 KB Think 페이지나 기사로 이동하게 했다.

`[portfolio]`는 아예 지운다. 자체 계산값에 출처를 붙이는 것은
**고객에게 아무 정보도 주지 않으면서 문장만 어지럽힌다.**

> 내부 표기와 대고객 표기는 **목적이 다르므로 같은 문자열을 쓰지 않는다.**
> `card_spec.advice` 는 태그가 박힌 내부 문구(검수·감사용),
> `advice_display` + `sources` 는 대고객용이다. → `src/sources.py`

### 2-2. 74자는 카드의 제약이었다

41케이스의 13~74자는 **현재 카드 UI 가 넣을 수 있는 양**이다. 설계 제약이
아니라 화면 제약이다. 채팅형으로 가면서 그 제약이 사라졌고, 그러자
문구 품질이 올라갔다 — 초판에서는 "변동 + 기여 + 원인"을 74자에 넣을 수 없어
LLM 이 계속 글자수로 반려됐다(실측: 4라운드 소비 후 폴백).

한도를 40~220자로 올린 뒤 **LLM 호출이 23회 → 15회로 줄고 폴백이 사라졌다.**
제약을 풀었더니 비용이 내려간 역설적인 결과다.

**폴백 문구에는 여전히 원본 제한(13~74자)이 적용된다.** 현업이 그 틀에서
쓴 문장이기 때문이다. → `config.ADVICE_*` / `briefing_agent.ORIGINAL_*`

### 2-3. 고객이 알고 싶은 것은 "왜"다

초판 문구는 "자산이 83만원 줄었어요"까지였다. 금액은 고객이 이미 화면에서
본다. 브리핑이 더할 수 있는 것은 **그 금액이 왜 그렇게 됐는지**이고,
그 답은 대개 그날 뉴스에 있다. 그래서 근거를 3층으로 만들었다.

```
market_tool   숫자   코스피 -3.39% · 원/달러 1,333원
retriever     해설   반도체 업종에 차익 실현이 번졌다
news_tool     사건   '반도체 약세' 코스피 6,500 내줘 — MBC뉴스   ← 신설
```

뉴스는 **보유 종목 비중 순으로** 찾는다. 비중이 큰 종목이 변동 설명력도
크기 때문이다. 종목명을 그대로 검색하면 "KODEX" 같은 상품 브랜드가 검색을
망치므로 섹터 어휘로 번역한다(`news_tool.query_for`).

### 2-4. 채팅형 UI — 다만 Runtime 에 LLM 은 없다

**이것이 이 개정에서 가장 오해하기 쉬운 지점이다.**

채팅처럼 보이는 것은 **연출**이다. 문구는 전날 Batch 에서 생성·3축 심사·
담당자 승인을 거쳐 JSON 으로 내려오고, 고객 진입 시점에는 그 JSON 을
순차로 펼쳐 보여줄 뿐이다. 모델을 부르지 않는다.

> 금소법상 투자 문구는 **사람 책임 하에** 노출되어야 한다.
> 고객 요청 경로에 LLM 을 넣으면 그 책임 구조가 성립하지 않는다.
> 검수 단위는 고객이 아니라 **케이스**다 — 41건을 검수하면 전 고객에게 나간다.

"AI 와 대화하는 느낌"은 **근거를 단계적으로 드러내는 방식**으로 얻는다.
한 번에 다 보여주면 정보량에 압도되고, 순차로 펼치면 읽힌다.
이것은 UX 선택이지 아키텍처 변경이 아니다.

### 2-5. 실제 AS-IS 화면을 반영 (`asis.png`)

실제 투자홈 캡처를 받고 세 가지를 고쳤다.

**① 주색이 노랑이 아니라 보라다.** 초판 기획서는 "KB 톤 노랑 #FFBC00"이라고
적었지만 실물 화면은 보라 계열(#6B4EFF 대)이다. 버튼·강조·배지가 전부 보라다.
**실물이 기준이다.** 노랑은 자산 영역 그라데이션과 보조 강조에만 남겼다.

**② 상승·하락 색이 반대였다.** 한국 증시 관례는 **상승 = 빨강 / 하락 = 파랑**이고
캡처의 `▲ 16.76 (0.26%)`도 빨강이다. 초판 뷰어는 반대로 칠해져 있었다.
금융 화면에서 이건 단순 취향이 아니라 **오독을 만드는 오류**다.

**③ AS-IS 가 카드 한 장이 아니라 "자리 하나 + 네 가지 후보"다.** 캡처의
설명 그대로다 — *"카드 자리 하나에 네 가지를 준비해두고, 접속하실 때마다
그중 하나가 노출됩니다."* 그래서 뷰어 왼쪽에 **네 슬롯을 모두 그리고
어느 하나가 뽑혔는지 표시**한다. `🎲 카드 다시 추첨` 버튼으로 같은 고객에게
다른 카드가 뜨는 것을 발표 중에 보여줄 수 있다. 이게 "랜덤의 문제"를
말로 설명하지 않고 **보여주는** 방법이다.

캡처의 시황 카드 구조(지수 pill + 🇰🇷/🇺🇸 뉴스 행)도 그대로 재현했다.

### 2-6. "콘텐츠 제공"이 아니라 "PB 제안"으로 보이게

초판 뷰어는 문구 아래 링크 목록이 이어지는 형태라 **콘텐츠 추천 화면**처럼
읽혔다. 브리핑의 정체성은 *"배분과 변동의 이유를 설명하는 것"* 인데
화면이 그걸 드러내지 못했다.

채팅 흐름을 **PB 상담 순서**로 재구성했다.

```
🧑 오늘 내 투자자산 어때?
✦ 오늘 시장부터 같이 볼게요
✦ [시황 보드]   코스피 · S&P500 · 원/달러 · 내 자산을 한 화면에
                   상승 빨강 / 하락 파랑 · 스파크라인 · 단기 전망 배지
✦ [내 투자자산] 큰 숫자 + 진단 배지(하락 · 과편중 · 최대비중 42% · CASE19)
✦ [무슨 일이 있었나요]  생성 문구 + ①②
✦ [어느 자산이 움직였나]  종목별 비중 바 + 기여액 (40% 넘으면 바가 앰버)
✦ [제가 본 점검 포인트]  ★ 신설
✦ [설명의 근거]  출처 카드
✦ [내 보유 종목 관련 오늘 기사]
✦ [이어서 읽어볼 콘텐츠]
✦ [엔드서비스 CTA]
```

각 블록에 **섹션 헤더**(● 제목 … 우측 출처 표기)를 달아 글이 줄줄이 이어지지
않게 끊었다. 초판은 카드 내부 `<span>` 들이 인라인이라 제목·요약·발행처가
**줄바꿈 없이 붙어 있었다** — `display:flex; flex-direction:column`으로 고쳤다.

#### ★ "제가 본 점검 포인트"

PB 느낌을 만드는 핵심 블록이다. **새 LLM 호출 없이** `card_spec.diagnosis`
(Rule 진단값)로 조립한다.

| 조건 | 노출 |
|---|---|
`gap_type == 과편중` | 한 종목에 N%가 몰려 있어요 — 기여 종목명과 함께 |
`gap_type == 과보수` | 위험자산 비중이 하우스뷰 권고(40%)보다 낮아요 |
`gap_type == 정합` | 지역 분산이 균형 범위에 있어요 |
해외 비중 ≥ 30% | 환율이 함께 움직여요 — 환헤지 여부로 체감이 달라요 |
`days_since ≥ 30` | N일 만에 오셨어요 — 기간을 나눠 보면 원인을 찾기 쉬워요 |

**투자권유가 되지 않도록 "확인해 보세요"까지만 쓴다.** 보유 구조와 하우스뷰
권고의 **차이를 설명**할 뿐이고 판단은 고객에게 남긴다. 뷰어 하단과 블록
우측에 "자동 진단 · 권유 아님"을 명시했다.

이 블록 때문에 `card_spec` 에 `diagnosis` 칸이 생겼다 — 기존에는 진단 결과가
`selection_reason` 문자열 안에만 있어서 화면이 재사용할 수 없었다.

### 2-7. 콘텐츠 매칭 — 진단과 상충하면 감점

과편중 고객에게 **"위험자산 비중이 너무 낮을 때 생기는 일"** 이 추천됐다.
두 글이 똑같이 `#자산배분` `#투자성향` 을 달고 있어서 태그만으로는 구분되지
않는다. `CONFLICT` 표와 `W_CONFLICT = -4.0` 감점을 넣었다.

```
과편중 ← "위험자산 비중이 너무 낮" · "과보수" · "단기자금" · "현금성"
과보수 ← "한 종목에 몰" · "집중" · "편중"
```

수정 후: 과편중 → *"반도체 ETF 한 종목에 몰렸을 때 — 분산의 실제 효과"*,
과보수 → *"위험자산 비중이 너무 낮을 때 생기는 일"*. 서로 제자리를 찾았다.

최근 30일 콘텐츠에 `W_RECENT = 0.6` 가점도 넣었다. 오늘 국면을 다룬 글이
먼저 와야 한다.

## 3. 범위에 들어온 것 / 들어오지 않은 것

**들어온 것**
- `src/news_tool.py` — Google News RSS. 보유 종목·섹터 기사
- `src/sources.py` — 내부 태그 → 대고객 출처 칩 렌더링
- `search_news` 노드 (병렬 fan-out 5번째)
- `card_spec.advice_display` · `sources` · `news` · `end_service`
- `data/kbthink_contents.json` 최신화 — 50건(9~10월 14건 추가) · `summary`·`url` 신설
- `data/reports/*.md` frontmatter 에 `url`·`summary`
- `demo/viewer.html` — 채팅형 좌우 비교 뷰어 + `build_viewer.py`
  · AS-IS 패널은 `asis.png` 재현 (보라 팔레트 · 탭바 · 4슬롯 랜덤 · 시황 카드)
  · TO-BE 패널은 PB 상담 흐름 (시황 보드 → 변동 → 설명 → 기여 → 점검 → 근거)
- `card_spec.diagnosis` — 화면이 재사용할 수 있는 Rule 진단값
- `content_matcher` 상충 감점 + 최근 30일 가점
- 문구 길이를 `.env` 설정으로 (`ADVICE_MIN_LEN`/`MAX_LEN`/`MAX_SENTENCES`)

**들어오지 않은 것 (의도적)**
- **Runtime LLM 호출** — 2-4 참고. 절대 넣지 않는다
- 카드 종류 추가 — 4종 고정. 채팅은 카드를 대체하는 표현이지 추가가 아니다
- 뉴스를 `contents` 와 합치기 — 뉴스는 `evidence`(검증 대상),
  KB Think 콘텐츠는 `contents`(검증 대상 아님). 성격이 다르다
- 뉴스 본문 크롤링 — 제목·발행처·링크까지만. 본문은 저작권 문제가 있고
  링크로 보내는 것이 고객에게도 낫다

## 5. 남은 결정

- **뉴스 출처의 신뢰도 관리** — Google News 는 매체를 가리지 않는다.
  대고객 노출이므로 매체 화이트리스트가 필요할 수 있다. 현재는 전부 통과
- **뉴스 저작권** — 제목·링크만 쓰므로 인용 범위로 보이지만 법무 확인 필요
- **AS-IS 캡처의 금액 마스킹** — 뷰어는 목데이터지만 실제 화면과 같은 위치를
  흐림 처리했다. 발표 자료에 캡처를 쓸 때 동일하게 가릴 것
- **엔드서비스 링크 형태** — `cases_41.json` 의 `window.navi.navigate(...)` 는
  앱 내부 네비게이션이다. 뉴스·KB Think 는 외부 URL 이라 처리 경로가 다르다
- `curAmt` 슬롯 미사용 · `CASE1~9` 미검증 · 중복 문구 4쌍 — 초판에서 이어짐
