## 7 · 핵심 코드 ① — Feedback Loop (3:50–5:00) 〔발표 요소 3〕

```
[화면]  코드 + 실패 시나리오

  reviews: Annotated[list, operator.add]      ← 이게 문제였다

  operator.add(["1회차 실패기록"], []) == ["1회차 실패기록"]

  1회차: compliance 실패 → 재작성
  2회차: 세 축 전부 통과
         그런데 1회차 실패기록이 남아 all(passed) 가 False
  → 3회 돌고 폴백. 반려된 문구는 절대 되살아나지 못한다.
```

▶ "이게 이 프로젝트에서 가장 찾기 어려웠던 버그입니다."

▶ "`reviews`는 세 심사 노드가 병렬로 쓰는 칸이라 **reducer가 반드시 있어야**
합니다. 없으면 `InvalidUpdateError`가 납니다. 그런데 `operator.add`로 두면
**그 칸을 비울 수가 없습니다.** 노드가 빈 리스트를 반환해도 누적분이 남습니다."

▶ "그래서 재작성해서 문구가 멀쩡해져도 1회차 실패 기록 때문에 **영원히 반려**됐습니다."

```
[화면 전환]  해결

  reviews        : Annotated[list, keep_latest_round]   현재 회차만
  review_history : Annotated[list, operator.add]        전 회차 — 감사 추적

  def keep_latest_round(old, new):
      merged = list(old or []) + list(new or [])
      if not merged:
          return []
      latest = max(r.get("revision", 0) for r in merged)
      return [r for r in merged if r.get("revision", 0) == latest]
```

▶ "한 칸에 *지금 판정에 쓸 값*과 *남겨야 할 이력*을 같이 담으려 한 게 원인이었습니다.
**수명이 다르니 칸을 둘로 나눴습니다.**"

▶ "각 심사 결과에 회차 번호를 박고, reducer가 그걸 보고 **스스로 이전 회차를 버립니다.**
노드가 '비워야 한다'를 기억할 필요가 없습니다. 기억에 의존하는 규칙은 언젠가
빠뜨리고, **빠뜨린 줄도 모릅니다.** 실제로 그랬습니다."

> 이 장이 "Agent 설계 구체성 35점"에 가장 직접 닿습니다. 시간을 아끼지 마세요.

# Q&A 대비

| 질문 | 답 |
|---|---|
**"LLM이 틀린 문구를 쓰면?"** | 3축 심사 → 최대 3회 재작성 → 그래도 안 되면 41케이스 **원본 문구로 폴백**합니다. 현업이 쓴 문장이라 컴플라이언스가 보증됩니다. 그다음 담당자 승인까지 거칩니다 |
**"비용은?"** | Batch 1일 41회, 건당 LLM 3.7콜. **Runtime에는 LLM이 없습니다** — 고객이 늘어도 비용이 안 늘어납니다 |
**"왜 고객이 자유롭게 질문 못 하나?"** | 금소법. 무엇을 물을지 모르면 답을 **미리 검수할 수 없습니다.** 미리 승인된 질문 칩만 제공합니다 |
**"할루시네이션은?"** | 문장 단위 grounding. `[portfolio]`는 자체 계산값이라 면제, 외부 주장은 evidence에 그 doc이 있어야 하고 LLM 2차로 본문 지지 여부까지 봅니다 |
